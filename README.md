# 🔔 بوت مراقبة تذاكر الأهلي على تذكرتي → إشعار Telegram

البوت ده وظيفته **يراقب ويبعتلك إشعار بس**. مفيهوش حجز أو شراء تلقائي، ومش بيحاول يتخطى أي CAPTCHA أو حماية. لو ظهر CAPTCHA، بيعتبر الفحص فاشل ويحاول بعد شوية.

## الفكرة ببساطة
- **GitHub Actions** (مجاني) بيشغّل الكود كل 5 دقايق على سيرفرات GitHub، فمش محتاج موبايل ولا كمبيوتر مفتوح.
- الكود بيفتح صفحة المباراة بمتصفح حقيقي (Playwright) لأن تذكرتي بتعتمد على JavaScript، وبيحدد الحالة: `AVAILABLE` / `SOLD_OUT` / `NOT_STARTED` / `UNAVAILABLE`.
- لو بقت **متاحة** → يبعت رسالة Telegram **مرة واحدة بس**، ويحفظ الحالة في `state.json` عشان ميكررش.
- لو رجعت مش متاحة وبعدين نزلت تاني → هيبعت إشعار جديد.

## الملفات
```
ahly-tickets-bot/
├── monitor.py                    ← الكود الأساسي
├── requirements.txt

├── .gitignore
└── .github/workflows/monitor.yml ← جدول التشغيل (كل 5 دقايق)
```

## الخطوة 1: جهّز Telegram (بما إنك عملت البوت)
محتاج حاجتين: **Token** بتاع البوت، و **Chat ID** بتاعك.

1. **Token**: اللي BotFather إداهولك، شكله `123456789:AAH...`. خليه سري.
2. **Chat ID**:
   - افتح البوت بتاعك في تليجرام واضغط **Start** وابعتله أي رسالة (مهم! من غير كده مش هيعرف يبعتلك).
   - افتح الرابط ده في المتصفح بعد ما تحط التوكن مكان `TOKEN`:
     `https://api.telegram.org/botTOKEN/getUpdates`
   - دوّر على `"chat":{"id":` والرقم اللي بعده هو الـ Chat ID (رقم، ممكن يبقى بالسالب لو جروب).
   - لو الصفحة فاضية (`"result":[]`)، ابعت للبوت رسالة تاني وحدّث الصفحة.

## الخطوة 2: ارفع المشروع على GitHub
1. اعمل حساب على github.com، واعمل **New repository** باسم `ahly-tickets-bot`.
2. اختار **Public**: الـ Actions مجانية بلا حدود على الريبو العام، لكن على الخاص فيه 2000 دقيقة/شهر بس (تكفي تقريبًا فحص كل 20 دقيقة). مفيش أي سر في الكود، كل حاجة حساسة في Secrets.
3. ارفع كل الملفات. مجلد `.github` مخفي، فلو صعب من المتصفح استخدم GitHub Desktop أو `git push`.

## الخطوة 3: ضيف الإعدادات
**Settings → Secrets and variables → Actions**

تبويب **Secrets** (سرّي):
| الاسم | القيمة |
|---|---|
| `TG_BOT_TOKEN` | التوكن من BotFather |
| `TG_CHAT_ID` | الـ Chat ID |

تبويب **Variables** (عادي):
| الاسم | القيمة |
|---|---|
| `MATCH_URL` | رابط صفحة المباراة على تذكرتي |
| `MATCH_NAME` | (اختياري) مثلًا `الأهلي × الزمالك` |
| `BOOK_SELECTOR` | (اختياري) CSS selector لزرار الحجز |

وكمان: **Settings → Actions → General → Workflow permissions → Read and write permissions** → Save.

## الخطوة 4: التشغيل والاختبار
1. **تجربة الإشعار**: **Actions → Ahly Tickets Monitor → Run workflow** → علّم **test_telegram** → Run. لازم الرسالة توصلك على تليجرام.
2. **تجربة الكشف**: Run workflow تاني من غير test، وعلّم **debug**. بعد ما يخلص نزّل الـ Artifact اسمه `debug`، فيه `page_text.txt` و `buttons.json` و `screenshot.png`. شوف الكلمات الفعلية على الصفحة.
3. بعد كده هيشتغل لوحده كل 5 دقايق.

> ⚠️ **مهم:** كلمات الكشف في `monitor.py` (`SOLD_OUT_WORDS` و `NOT_STARTED_WORDS` و `BOOK_WORDS`) تخمين مبني على صياغة شائعة، ومتأكدتش منها على صفحة تذكرتي الفعلية. اعمل تجربة الـ debug مرة وعدّل الكلمات حسب اللي بتشوفه. لو الصفحة بتعرض فئات متعددة، "Sold Out" على فئة واحدة ممكن يخلي الكشف يعتبرها كلها نفدت.

## التعديلات
- **تغيير رابط المباراة**: Variables → عدّل `MATCH_URL` (ومعاه `MATCH_NAME`). لو المباراة جديدة، صفّر `state.json` لـ `{"status":"UNKNOWN","notified_available":false,"last_checked_date":""}`.
- **تغيير مكان الإشعار**: عدّل Secret `TG_CHAT_ID` (ممكن جروب فيه صحابك، ضيف البوت للجروب).
- **تغيير مدة الفحص**: في `.github/workflows/monitor.yml` عدّل `cron: "*/5 * * * *"`. أقل مدة 5 دقايق، و`*/10` يعني كل 10. GitHub مش بيضمن الدقة بالثانية.

## ملاحظات
- GitHub بيوقف الـ workflows المجدولة لو الريبو ماحصلش فيه نشاط 60 يوم. البوت بيكتب تاريخ آخر فحص في `state.json` مرة يوميًا فده بيحافظ على النشاط. لو اتوقف، فعّله يدويًا من تبويب Actions.
- افحص بمعدل معقول واحترم شروط استخدام تذكرتي.
- لو إرسال Telegram فشل، البوت **مش** بيسجل إنه بعت، فهيحاول تاني في الدورة الجاية.
- لو شاركت التوكن بالغلط في أي مكان، اعمل له `/revoke` من BotFather واستبدله.
